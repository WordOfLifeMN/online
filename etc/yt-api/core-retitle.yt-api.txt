# -- WHY THESE USE --input AND NOT --title -------------------------------------
#  yt-api does NOT read the existing resource before updating. It builds a fresh
#  one from whatever you pass (internal/commands/update.go, updateVideo), and
#  YouTube's videos.update deletes any mutable property the body leaves out. So
#    yt-api update videos --id X --title '...'
#  would blank the description, categoryId, tags and defaultLanguage.
#
#  Adding --part snippet does NOT fix it. yt-api always allocates a status
#  object, so the body still carries 'status' while the part list no longer
#  declares it, and the API rejects the call:
#    {\
#  (Confirmed against video Zq8IdYXb2nM on 2026-10-12. The call was rejected, so
#  nothing was modified.)
#
#  There is also no flag for defaultLanguage, which 46 of the 47 videos have set.
#  So each call below sends a complete JSON body instead: the live snippet and
#  status, verbatim, with only the title changed.

# -- --dry-run DOES NOT VALIDATE THESE -----------------------------------------
#  handleUpdateDryRun only echoes the command-line flags; it never opens the
#  --input file and never checks --part. A dry-run of these calls will print
#  empty fields and tell you nothing. That is exactly why the earlier --part
#  snippet form passed its dry-run and still failed for real.

# -- SUGGESTED ORDER OF WORK ---------------------------------------------------
#  1. Run ONE video call. Confirm in YouTube Studio, or re-list it and compare
#     against etc/yt-api/core-retitle/videos/<id>.json - everything except the title
#     should be byte-identical.
#  2. Then the remaining videos, then the playlists.
#  To run the whole file once you are happy:
#     Get-Content etc/yt-api/core-retitle.yt-api.txt | Where-Object { $_ -like 'yt-api*' } |
#       ForEach-Object { Invoke-Expression $_ }
